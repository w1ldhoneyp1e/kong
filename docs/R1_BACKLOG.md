# R1 Backlog

## Цель релиза

Первый релиз Kong Store - публичный сайт-каталог с корзиной и оформлением заказа без онлайн-оплаты.

Основной сценарий:

1. Покупатель открывает каталог.
2. Находит товар через категории или поиск.
3. Открывает карточку товара.
4. Выбирает доступный вариант товара.
5. Добавляет товар в корзину.
6. Оформляет заказ с контактами и адресом.
7. Менеджер видит заказ в админке и обрабатывает его вручную.

Онлайн-оплата не входит в R1, но поток должен быть построен так, чтобы позже включить оплату настройкой, без замены каталога, корзины и checkout.

## Режим продаж

Нужна настройка магазина:

```ts
commerce_mode: 'manual_checkout' | 'online_payment'
```

Для R1 активен `manual_checkout`:

- корзина включена;
- checkout включен;
- заказ создается без онлайн-платежа;
- менеджер обрабатывает оплату и доставку вручную.

Для следующих релизов `online_payment` должен включать платежный шаг и платежные статусы без переписывания покупательского пути.

## Что уже есть в коде

- Публичная витрина: главная, каталог, страница категории, карточка товара, поиск.
- Корзина: создание cart, добавление variant, базовая страница корзины.
- Checkout: базовая форма и вызов `/store/carts/:id/complete`.
- Аккаунт покупателя: регистрация, вход, профиль, история заказов.
- Админка: категории, товары, заказы, покупатели, staff.
- RBAC: staff users, роли, permissions, проверка permissions на backend routes.
- Backend: Medusa v2, Store API proxy, кастомные staff/RBAC-модули.

## Как учитывать готовность админки

Админка - часть того же commerce-домена, что и публичная витрина. Для R1 ее не нужно проектировать как отдельное приложение с нуля: она уже является back office для каталога, покупателей, staff и заказов.

Текущая готовность по модулям:

- Категории: управление уже готово близко к R1, нужны в основном проверка UX, permissions и связка с публичным каталогом.
- Товары: CRUD уже есть и близок к рабочему состоянию, но R1 требует усилить именно продажную часть товара: variants, SKU, цены, наличие, публикацию и отображение выбранного variant на витрине.
- Покупатели: CRUD в окологотовом состоянии, для R1 нужен hardening, проверка связки с заказами и правами доступа.
- Staff: CRUD и RBAC уже есть, для R1 нужен не новый модуль, а доведение permissions под контент-менеджмент и ограничения действий в UI/backend.
- Заказы: список и карточка уже есть, главный R1-фокус - ручной workflow обработки заказа после checkout.

Поэтому задачи ниже нужно читать как "довести существующую основу до релизного поведения", а не как "создать все заново".

## Главные пробелы R1

### 1. Product domain

Сейчас CRUD товара уже есть, а товар на витрине использует первый variant. Для R1 нужно не переписать CRUD, а довести товарную модель до продажного состояния: товар должен продаваться через явный доступный variant.

Задачи:

- В существующей админке товара довести управление описанием, вариантами, SKU, ценой и базовым наличием.
- Для простого товара создавать минимум один variant.
- На карточке товара показывать варианты и давать выбрать variant перед добавлением в корзину.
- На листинге показывать цену выбранного/минимального доступного variant.
- Не давать добавить товар без доступного variant.
- Определить базовые статусы публикации: `draft`, `published`, `hidden`.
- Разделить право редактирования каталога и публикации: `catalog:manage` и `catalog:publish`.

### 2. Public catalog

Каталог должен выглядеть как релизный публичный сайт, без технических заглушек.

Задачи:

- Проверить главную, каталог, категории, поиск и карточку товара на пустые состояния.
- Убрать или заменить моковую страницу `/products`.
- Исправить промо-ссылки на несуществующие категории, если таких категорий нет.
- Подготовить страницы из footer: доставка, оплата, возврат, FAQ/поддержка или убрать ссылки до появления страниц.
- Улучшить отображение цены, наличия и недоступных вариантов.
- Добавить базовые SEO metadata для каталога и карточек.

### 3. Cart

Корзина уже есть, но можно считать, что ее нет. Для R1 она должна быть полноценной частью продукта.

Задачи:

- Показывать название, variant, цену, количество и сумму по строке.
- Добавить изменение количества.
- Добавить удаление позиции.
- Пересчитывать итоговую сумму после изменений.
- Запретить переход к checkout из пустой корзины.
- Очистить localStorage cart id после успешного заказа.
- Добавить счетчик корзины в header.

### 4. Checkout без онлайн-оплаты

Текущий checkout собирает поля визуально, но не привязывает их к заказу как полноценные данные.

Задачи:

- Валидировать обязательные поля: имя, телефон, email, город/адрес.
- Сохранять контактные и shipping данные в cart перед complete.
- Добавить комментарий к заказу.
- Поддержать ручной способ доставки/обработки.
- После successful complete показывать страницу/состояние "заказ принят".
- Корректно показывать ошибки Medusa complete.
- Убедиться, что заказ создается без online payment в режиме `manual_checkout`.

### 5. Admin orders

Админка заказов уже есть в том же домене, что и checkout. Ее нужно довести до ручного workflow обработки заказов, а не строить отдельный операторский инструмент.

Задачи:

- Проверить, что backend route для order detail/update/delete экспортирует handlers.
- Показывать в заказе контакты, адрес, комментарий, состав заказа, variant, количество, цены и итог.
- Добавить понятные статусы ручной обработки: `new`, `processing`, `confirmed`, `completed`, `cancelled`.
- Разделить системный статус Medusa и внутренний статус обработки, если Medusa-статусов недостаточно.
- Добавить фильтры по статусу и поиск по email/номеру заказа.
- Запретить опасное удаление заказов для ролей без нужного permission или заменить удаление на отмену.

### 6. Roles and permissions

Staff/RBAC уже есть. Для R1 нужен контент-менеджмент на permissions, а не только жесткие роли и доступ к разделам.

Базовые роли-пресеты:

- `owner`: все права.
- `admin`: каталог, заказы, покупатели, staff, настройки.
- `content_manager`: товары, категории, медиа, документы, публикация по отдельному праву.
- `order_manager`: заказы и покупатели.

Базовые permissions:

- `catalog:manage`
- `catalog:publish`
- `media:manage`
- `orders:manage`
- `customers:manage`
- `staff:manage`
- `settings:manage`

Задачи:

- Добавить недостающие permissions миграцией.
- Обновить admin navigation под новые permissions.
- В админке скрывать/блокировать действия, а не только страницы.
- На backend проверять permission на каждое изменение.

### 7. Commerce settings

Нужна точка управления режимом продаж.

Задачи:

- Выбрать место хранения: Medusa module, store metadata или отдельная settings table.
- Добавить backend API для чтения/изменения commerce settings.
- Добавить страницу или блок в админке для toggles.
- На витрине читать режим и управлять checkout/payment поведением.
- В R1 оставить online payment выключенной.

### 8. Content pages

Для публичного сайта-каталога нужны базовые страницы доверия.

Задачи:

- О нас.
- Контакты.
- Доставка.
- Оплата.
- Возврат.
- Политика/оферта, если клиенту нужна публичная продажа через корзину.

### 9. Mobile and responsive

Адаптив для всех клиентских интерфейсов - обязательное условие R1. Без рабочей мобильной версии релиз не едет.

Клиентские интерфейсы R1:

- главная;
- каталог и страницы категорий;
- поиск;
- карточка товара и выбор variant;
- корзина;
- checkout;
- страницы входа, регистрации и профиля покупателя;
- контентные страницы;
- header, footer, навигация, account/cart actions.

Задачи:

- Проверить все клиентские экраны на мобильных, планшетных и desktop viewport.
- Убрать горизонтальный scroll, наложения текста, обрезанные кнопки и некликабельные элементы.
- Сделать touch-friendly размеры контролов, вариантов товара, кнопок количества и checkout-полей.
- Проверить sticky/header поведение на мобильном.
- Проверить полный мобильный путь: каталог -> карточка -> корзина -> checkout -> заказ принят.
- Зафиксировать мобильную проверку в R1 acceptance checklist.

### 10. Release readiness

Задачи:

- Добавить smoke-тест на главную, каталог, карточку товара, корзину, checkout. Для R1 тесты будут ручными
- Добавить тесты на product API mapping и cart helpers, если появятся.
- Проверить мобильную версию по `Mobile and responsive` checklist.
- Подготовить seed-данные: категории, несколько товаров с вариантами, staff-роли. Чисто для тестирования, потому что продуктовые данные будут вноситься отдельно
- Проверить env для frontend/backend.
- Обновить deployment docs после появления settings/migrations.

## Предлагаемый порядок работ

1. Variant, price, availability в админке товара.
2. Выбор variant на карточке товара.
3. Полноценная корзина: quantity/remove/totals.
4. Checkout manual order: контакты, адрес, comment, success state.
5. Admin order detail/workflow.
6. Permissions для content manager.
7. Commerce settings.
8. Мобильный адаптив всех клиентских интерфейсов.
9. Публичные страницы и релизная полировка.

## Не входит в R1

- Онлайн-оплата.
- Интеграции доставки.
- Автоматический складской учет.
- Сложные фильтры по специфическим характеристикам скалолазного снаряжения.
- Заявки "по запросу" вне корзины.
- Сравнение товаров.
- Массовый импорт CSV/XLSX.
