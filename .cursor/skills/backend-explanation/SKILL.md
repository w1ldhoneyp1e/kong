# Объяснение изменений на бэкенде

Используй в каждом ответе, где затронуты файлы под `backend/`. Пиши на русском, без дублирования очевидного кода.

## Шаблон (после блоков с кодом)

### Что сделано

- Перечисли изменённые/новые файлы и одну фразу на файл (роль: роут, сервис, миграция, модель).

### Связь с существующим кодом

- Откуда вызывается новый код (какой роут, какой модуль из `req.scope`).
- Что осталось без изменений и почему это нормально.

### Паттерны и почему так

- Например: тонкий handler → сервис → модель ORM; DTO в роуте; проверка прав через существующий helper.
- Если выбор неочевиден — одно предложение «альтернатива и почему не она».

### Как проверить

- Команда или HTTP-запрос / сценарий в админке.

Держи весь блок **компактным** (примерно полэкрана текста), если изменений немного.
